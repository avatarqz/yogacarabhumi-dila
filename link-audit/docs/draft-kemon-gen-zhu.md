## 1. 三層模型

| 層 | 是什麼 | 本專案的实體 | 儲存原則 |
|---|---|---|---|
| **原文** | 論本本文，一切對照的基準 | 《瑜伽師地論》T1579（100 卷） | **只存一份**，永不重複；所有科文/注文都錨定到它的段落 |
| **科文** | 科判大綱（階層節點），不含論本本文 | 韓清淨科（披尋記）、遁倫科（瑜伽論記）、基科（略纂）、DILA 科 | 每套科判獨立儲存；每個節點指向原文的一个 span |
| **注文** | 釋論的解釋文字 | 瑜伽師地論釋 T1580、瑜伽論記 T1828、略纂 T1829、披尋記 PXJ-H、分門記 T2801、手記 T2802、問答 T2259 | 每段注文錨定到原文 span（或科文節點） |

**關鍵原則**：原文是「被指向者」，科文与注文是「指向者」。三者物理分離，靠**位址**關聯，不靠複製文字。

**注意双重角色**：披尋記、瑜伽論記、略纂这幾部「既有科判又有釋文」——拆分時按**角色**拆，不是按書拆。同一部書的科判部分進科文庫、釋文部分進注文庫。

## 2. 定址方案（草案的基石）

**原文用大正頁欄定址（`頁.id`），不用 kpD。** 理由（已查證）：
- CBETA `taisho.adb` 的 T1579 已有 **1,805 個頁欄標記**（T30 pp.279–882 完整覆盖）。
- `anchorVa`（page-text.ts:74）**现在就解析 `頁.id`**（如 `30p328c`）——不必等新的通用錨點功能。
- 頁欄是版本內穩定座標，且本庫引文已用「大正30，328c01」这种寫法，天然对接。

**span 的精度**：一個科文節點通常对应原文的一段（跨數行）。用 `<嵌 i="原文庫?頁id" j="起行-止行">` 的 `j=` 行區間表达（`嵌` 已支援 `j=`，embed.ts:4）。頁id 定到欄、`j=` 定到行，合起來就是精确 span。

**科文節點自身的 id**：仍用 kpD（系列內流水號），但**跨庫引用原文時用頁欄**，不用 kpD。kpD 只在「科文庫內部」与「科文對科文」時用——後者才需要那个待做的通用錨點功能。

> 这樣切的好處：**核心功能（科文→原文嵌入）现在就能做**，通用錨點功能只是「科文對科文導航」的加分項，不是阻塞項。

## 3. 物理結構：兩種方案

### 方案 A（推薦）：多庫分儲，跨庫嵌入

```
ybh-gen.adb        原文庫：T1579 論本，带 頁.id 頁欄標記（可直接從 taisho.adb 的 T1579 抽出）
ybh-ke-han.adb     科文庫・韓清淨科：科判樹，節點 <嵌 i="ybh-gen?30pXXX" j="…">
ybh-ke-dun.adb     科文庫・遁倫科
ybh-ke-ji.adb      科文庫・基科
ybh-zhu.adb        注文庫：各部釋文，段落錨定原文 span（或按書分 ybh-zhu-1580.adb 等）
```

- 讀者開一個科文庫 → 看到該套科判樹 → 點節點，`<嵌>` 把原文对应段嵌入 → 再點注文可展開釋文。
- 換科判＝開另一個科文庫（或同一閱讀器裡切換分頁）。
- **优点**：原文只存一份；加新科判不动原文；各層獨立演化；完全符合「分儲」。
- **代价**：跨庫導航（accelon26 已支援多庫分頁与跨庫 `<嵌>`）；需要原文庫的頁欄標記。

### 方案 B（备选）：單庫多樹，科文以零寬標記共置

- 一個 ADB，原文是正文；每套科判在原文的对应边界插入**自閉合零寬標記**（`<科Han14 n="…"/>`、`<科Dun14 n="…"/>`），用 `<隱>` 或自閉合使其不渲染。
- 多個 `<樹>` 宣告，每套科判一个樹（`t="篇,章,科Han01,…"` / `t="篇,章,科Dun01,…"`）。
- 讀者選目錄樹＝選科判；點節點捲到原文该位置。**span 是隱含的**（由此節點到下一同層節點），不需 explicit 位址。
- **优点**：單檔、無跨庫； closest 到你最初提的「多 `<樹>`＋`<隱>`」構想；科文→原文不需位址解析。
- **代价**：多套科判的边界标記共置在同一文字流（零寬標記可共存，但正文会夹帶大量隱藏標記）；注文仍要另想（嵌或共置）；「分儲」是邏輯分儲而非物理分儲。

### 取捨建議

| 面向 | 方案 A 多庫 | 方案 B 單庫多樹 |
|---|---|---|
| 符合「分儲」字面 | ✅ 物理分儲 | △ 邏輯分儲 |
| 原文不重複 | ✅ | ✅ |
| 现在就能做（不待新功能） | ✅ 用 頁.id | ✅ 用共置標記 |
| 加新科判的干淨度 | ✅ 独立庫 | △ 要往正文插標記 |
| 注文整合 | ✅ 嵌 | △ 需另設 |
| 讀者換科判 | 換庫/分頁 | 換目錄樹（最直覺） |
| 實作复杂度 | 中（跨庫） | 中（多樹共置） |

**我的傾向：方案 A 為主**（符合你「分儲＋嵌/融」的明確要求、各層干淨），**但方案 B 的「選目錄樹換科判」體驗最直覺**，值得保留为閱讀端的一个視圖。两者不互斥：可以 A 儲存、閱讀端提供「把某科文庫的樹掛到原文上」的融視圖。

> **定案（§0）**：採 **B**（單庫多樹），但原文一層維持 A 的精神——**外掛 taisho.adb、不進庫**。即「科文＋注文＝庫內多樹；原文＝跨庫聯結」。方案 A 的 `ybh-gen.adb` 取消。

## 4. 庫內結構（定案版 XML 草案：單庫 ybh.adb 多樹）

### 4.1 樹宣告（頁籤＝選科判／選釋論）
```xml
<集 t="集">瑜伽師地論漢文集成</集>
<隱><樹 s="*" t="篇,章,韓01,…,韓54.">科判・韓清淨</樹></隱>
<隱><樹 s="*" t="篇,章,遁01,…">科判・遁倫</樹></隱>
<隱><樹 s="*" t="篇,章,基01,…">科判・基</樹></隱>
<隱><樹 s="*" t="篇,章,科01,…,科54.">科判・DILA</樹></隱>   ← B1 已建、已驗證
<隱><樹 s="*" l="註,釋" t="書,段.">注文（合一庫）</樹></隱>
```
- 每個 `<樹>` 一個目錄頁籤（search.ts:340），讀者換頁籤＝換科判——方案 B 的核心體驗。
- `t=` 同時登記快取標籤（漏了目錄 label 會空，B1 已踩過）。各套科判用不同標籤名前綴（韓/遁/基/科），互不串樹。

### 4.2 科文節點 → 原文（指 taisho.adb，不抽文字）
```xml
<章>卷第1</章>
<韓03 n="kpD03-001">問答標列十七地名</韓03>
<聯 i="taisho?30p279a">〔原文 30p279a〕</聯><嵌 i="taisho?30p279a" j="3-8" q="如是我聞" n="CBETA T1579"/>
…
```
- **`<聯 i="db?頁欄">` 負責跳轉與反鏈**：右欄開 taisho 該頁，標題下自動出現「反鏈 N · ybh → taisho」（README §373）——這就是定案 1 說「可以不抽文字」還能「有反鏈」的機制。
- `<嵌>` 負責行內速覽 span（`j=` 行區間）。
- 頁欄用 **CBETA 原生的 `<頁>` 標記**（taisho.adb T1579 實測 1,805 個），`anchorVa` 現在就解析。

### 4.3 注文（合一庫，就在 ybh.adb 內）
```xml
<書>瑜伽師地論釋（最勝子）</書>
<段 n="z1580-001"><聯 i="taisho?30p279a">30p279a</聯>
<嵌 i="taisho?30p279a" j="3-8" n="所釋原文"/>
釋曰。此中問者…（注文本文）
</段>
```
- 不按部拆檔（定案 4）：七部釋文同庫，各以 `<書>` 分群、共用「注文」樹。
- 注文对原文的對應，初期用「引文開頭句」匹配（注文常引原文起句），精确對齐属 span 工程（定案 2 半自動）。
- DILA 標點本（T1579 現況）仍留在庫內作对照 witness；T1581/T1582（定案 5）照舊為菩薩地 alternate witness，原文同樣可 `<聯 i="taisho?…">` 指過去。
