# R8：loadTree 封閉詞彙——讓「總目錄」頁籤只剩書目與卷

> ybh 工作區・2026-11-13・給 accelon26。使用者定案的新開卷體驗：**一開 adb 瞬間看到目錄樹（只列書與卷），切到哪個科判頁籤才建哪棵科判，不要擠在一起。**
> 資料端 v15 已備好（ybh.adb 現 18 棵樹宣告：`總目錄 t="篇,章."`、`瑜伽師地論科判 t="篇,章,科01…科54."`、16 棵家族純科判樹），**現況差一條 reader 規則**。

## 1. 實測到的現行行為（bench 可復現）

`總目錄` 宣告 `t="篇,章."`（應只 377 行），但 `loadTree` 的鏈展開（search.ts:592–616）會沿**實例 t=** 走：讀到 `篇` 的 `t="章,科01,…,科54."` 就把 54 個科判標籤拉進鏈 → 該頁籤仍載入 24,213 行、build 72ms。家族頁籤同理會被 篇.t 污染詞彙（目前靠 科X01 自宣告不越界，但語義上每個頁籤都「聽到了別人家的鏈」）。

## 2. 請求：鏈展開只認本樹宣告的詞彙（封閉世界）

在 `loadTree` 的 chain 展開迴圈加一條過濾：**實例 t= 裡不在 `start.tiers`（本樹宣告的層級集合）的標籤，忽略不展開**。

- 效果一：`總目錄` 只載 篇,章 ＝ **377 行、build 個位數 ms → 開庫即見**。
- 效果二：各頁籤詞彙互不串——主幹樹（篇,章,科01…54）照常全嵌套（其 t= 都在自己詞彙內）；家族樹（科X01…）照常（科X01.t 的子鏈都在自己詞彙內）。
- 效果三：`nodeAnchorIndex` 的 nsTag/volTag（最長鏈首兩層＝篇,章）**完全不受影響**——主幹樹仍是 56 層最長。
