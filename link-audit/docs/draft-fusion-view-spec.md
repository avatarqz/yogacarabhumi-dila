## 1. 資料形態（已凍結在 fixture）

- 論本只存一份（`篇 GW`）；每套科文（`篇 KE` 韓科、`篇 JI` 基科）以**透明容器**指向論本節點：
  ```xml
  <科02 n="ke-b">五識身</科02>
  <融 i="fix?GW-1#kpD02-001" n="原文・五識">（融視圖開啟時填入論本）</融>
  ```
- `i="db?W-V#kp"` ＝既有 `anchorVa` 全鏈（頁 id→塊.段→節點錨點），**不新增解析規則**。
- 缺目標樣本：`<融 i="fix?GW-1#kpD02-999">` → 解析 null，專供回退斷言。
- standoff 樣本：KE 與 JI 的 `<融>` 指向**同一** `GW-1#kpD01-001`（V5 已證同 VA）。

## 2. 視圖語義（要 accelon26 實裝的六件事）

| # | 行為 | 斷言 |
|---|---|---|
| 1 | **默認視圖**：`<融>` 維持現行透明容器——內容原樣顯示，不加晶片（向後兼容，taisho 舊用法不動） | 現況即合格 |
| 2 | **融視圖開關**：閱讀器級 toggle（建議放目錄面板，標題「以科文融合顯示」）。開啟時，每個 `<融>` 佔位內容被**目標子樹 span** 覆寫填入：`nodeSpanText(va, nodeSubtreeEnd(va), max=200)`，外殼標 `n=` 來源＋頁欄出處 | V6 |
| 3 | **回退**：目標解析 null → **保留佔位原文**＋狀態欄 warn（「缺目標 kpD02-999」），絕不空白 | V7 |
| 4 | **切換科文樹**＝重排同一份論本：目錄頁籤選 KE 或 JI 時，視圖按該樹 `<融>` 序列取段；論本文字不被複製、兩樹結果各自正確（span 相同來源） | V8 |
| 5 | **交互**：視圖內點科判標題＝ `<節聯>` 行為（捲動＋高亮＋目錄游標）；點填入的論本段＝可選跳 taisho 原文（若 i 指向跨庫） | V9 |
| 6 | **效能閘**：span 逐段延遲取（展開到可見才取），大科 200 行上限、`max` 屬性可覆寫；單次視圖重建不得同步拉 >50 段 | V10 |
