# 提示詞：給 adb-converter 工作區 —— 通用節點錨點解析（让科判節點可聯可嵌）

> 這份是給 `D:\2026\adb-converter` 工作區的開發提示詞，由 yogacarabhumi-dila 專案提出。
> 目標：让「結構節點」（如科判）能像大正頁碼一樣成为 `<聯>`／`<嵌>` 的目标，
> 以支援「科文／原文／注文分儲、多套科判指向同一份原文」的閱讀體驗。
> 請先讀完「現狀」再動手——很多基礎設施已經存在，**不要重造**。

## 1. 背景與最終用途

我們把《瑜伽師地論》漢文集成打包成 `ybh.adb`（已放 `D:\accelon3\ybh-v2.adb`）。結構：
- `篇`（18 部著作）＞`章`（411 卷）＞`科01…科54`（科判層級，深度＝科判 tier）。
- 每個科判節點帶錨點屬性：`<科14 n="kpD14-020">N1 出體</科14>`。
- 樹宣告：`<隱><樹 s="*" l="註,釋" t="篇,章,科01,…,科54.">目錄</樹></隱>`。

最終想做的閱讀體驗（使用者明確要求）：
1. **科文／原文／注文分開儲存**，用 `<嵌>`／`<融>` 在閱讀時疊合。
2. **多套科判（披尋記／遁倫／略纂）都指向同一份原文**，讀者選哪套科判就用哪套導航，原文不变。
3. 科判之間的互鏈、以及「科判節點 → 原文段落」的嵌入，都要**可點**。

## 2. 現狀（已查證，附檔名行號）

**已有的定址能力（`ts/src/accelon26/page-text.ts`）：**
- `anchorIndex(r)`（:30）：**只索引 `頁.id`**（大正頁碼 `30p328c`），外加 書/卷/冊/聯 供導航。
- `anchorVa(r, anchor)`（:74）：先試 頁.id；不是 頁 就退回 `locatorVa`。
- `locatorVa(r, anchor)`（:196）＋ `LOCATOR_RE`（:139）：解析 `塊.段[:句][#詞]`（如 `a6.7`、`d1.7:3`、`rv.10.90.3`），用 `attributes/塊.id` 与 `attributes/段.n`。塊 id 可多層。

**已有的嵌入（`ts/src/accelon26/embed.ts`）：**
- `<嵌 i="db?page" q="引文" j="12-34" n="label"/>`（:4）：點晶片去目標庫取引文插入，可跨庫。
- `openEmbed`（:57）把 `i=` 拆成 `db` + `anchor`，呼叫 `xref.ts` 的 `renderEmbed(db, anchor, q, j, label)`。
- `<融>` 在 `render_accelon3.ts`（:859 附近）目前是**透明容器**；`<嵌始>` 是零寬段首標記。

**已有的字典連結（`ts/src/accelon26/link.ts`）：**
- `buildEntryIndex`（:503）／`linkToEntry`（:528）：`<聯 n="詞">` 只解析**字典條目**（詞/字/詞目/字頭/term/entry 的快取名稱表），不解析結構節點。

**缺口（一句話）：**
`科NN.n="kpD14-020"` 這種**結構節點錨點**，`anchorVa` 的兩套路（頁.id、塊.段）都解析不到，`linkToEntry` 也只認字典條目。所以科判節點目前**不能被 `<聯>` 跳到、也不能被 `<嵌 i="ybh?kpD14-020">` 嵌入**。

## 3. 請求的功能（核心，最小改动）

**让 `anchorVa` 支援「通用節點錨點」：依「標籤＋id/n 屬性」解析到該節點的 VA。**

具體：
- 新增一种錨點解析路徑：給定一个「錨點標籤集合」（例如樹 `t=` 裡宣告的層級標籤 科01…科54，或一個約定的錨點標籤如 `<錨 id="…"/>`），把這些標籤實例的 `n=`（或 `id=`）屬性值建成 `值 → VA` 索引（復用现有 `attrVas(r, tag, attr)`，page-text.ts:108 附近已有這個工具）。
- `anchorVa(r, anchor)` 在 頁.id 与 塊.段 都失敗後，再試這個通用節點索引。
- 这样 `<嵌 i="ybh?kpD14-020">` 与 `<聯>`（見下）就能解析到科判節點。

**設計约束（重要）：**
- **向後相容**：頁.id 与 塊.段.句 的现有行為完全不变；现有 taisho/wxzj/13j/sz 等庫不受影響。
- **不要硬塞語義**：不必把科判改成 塊/段/頁——那会扭曲現有定址語義。通用節點錨點是獨立的一條路徑。
- **多著作合庫的命名空間**：`ybh.adb` 含 18 部著作，`kpD03-001` 在不同著作裡会重複（它是「系列內」流水號）。請支援**带命名空間的錨點**，例如 `T1579#kpD03-001` 或 `ybh:T1579/kpD03-001`，解析時先按命名空間縮小範圍。具體語法由你定，但要能區分同 id 的不同著作節點。（若建議「每部著作各自一庫」來避免撞號，也可，請在回覆裡說明取捨。）
- **效能**：索引要快取（復用 `indexCache`/`WeakMap` 模式），不要每次解析都重掃 attributes。

**可選（同一條路徑順带）：**
- 让 `<聯 n="…">` 在字典條目找不到時，退回通用節點錨點解析（即 `linkToEntry` 失败後試 `anchorVa`），这样科判互鏈不必改標籤就能點。若你認為用新標籤（如 `<節聯>`）更乾淨，也可以，請說明。

## 4. 驗收標準（請附可重跑的測試）

1. 用 `ybh-v2.adb`（或一個含 `<科14 n="kpD14-020">` 的最小測試庫）：
   - `anchorVa(r, "kpD14-020")`（單著作庫）回傳該科判節點的 VA，且 `mapper.lineOfVa(va)` 落在 `<科14 …>` 那一行。

2. `<嵌 i="ybh?kpD14-020" n="出體"/>` 點開後，嵌入的內容是該科判節點及其下原文（不是空白、不是报错）。
3. 回归：`anchorVa(r, "30p328c")`（taisho）与 `anchorVa(r, "a6.7")`（sz 風格 塊.段）行為与改动前一致。

## 5. 第二階段（可選，先不做，仅告知方向）

`<融>` 目前是透明容器。最終想要一个「**融視圖**」：選定一套科文（科判樹），把原文按該科判的節點-span 對應重排顯示；切換科文就切換視圖，原文不变。这需要：
- 科文節點 → 原文 span 的對應表（我們会在 yogacarabhumi 側用跨版本對齐產生，見該專案 `link-audit/docs/SUMMARY.md` §十二/十五）。
- `<融>` 或新標籤承載「以某科文樹組織某原文」的語義。
**這階段先不动**，等核心錨點解析穩定、且我們備好節點-span 對應表再談。
