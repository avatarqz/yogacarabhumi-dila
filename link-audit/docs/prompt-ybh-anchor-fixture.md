## 1. 背景：为什么需要 fixture

把测试指向现行 `ybh.adb` 后跑出 **48 passed / 4 failed**，4 条全是「数据改版」造成的断言失配，**不是 exe 或锚点码的问题**：

| # | 断言 | 失配原因（你们改版） |
|---|---|---|
| 1 | `PXJ-H#kpD03-001` 落在 `<科03 n="kpD03-001">` | v9 披寻记标题改干支，层级/标题变了（能解析，但不是 `科03`） |

正式库继续演进，测试就会反复红。所以给测试一份**冻结的最小样本**，正式库怎么改都不影响它。

## 2. 请求交付物

一个**确定性、可重跑**的 fixture，二选一（推荐 a）：

- **(a) 生成脚本**：`link-audit/tools/make-anchor-fixture.ts` → 产出 `anchor-fixture.adb`（几 KB～几十 KB，节点见 §3）。每次跑内容逐字节相同（固定 buildTime 或不含时间戳）。附一行 `sha256` 便于核对。

命名与路径你定，回信时告知；我们这边把 `anchor-node.test.ts` 的 `--v3/--v4`（可能还有 `--ybh`）指到它即可。

## 3. fixture 必须满足的内容（逐条对应断言）

结构：`篇 > 章 > 科01…科NN`；`篇.id`＝work 码、`章.id`＝`W-V`；`树 t="篇,章,科01,…,科NN."`。

**A. 篇级 / 卷级（v2、v3 段）**
- 两个 `篇`：`id="T1579"`、`id="PXJ-H"`（章 id 如 `T1579-1`、`PXJ-H-1`）。
- `T1579-1` 里有一个 `<科14 n="kpD14-020">…明其中可得诸法…</科14>`（给 bare `kpD14-020` 用，文件序第一笔即命中它）。
- `kpD03-001` 同时出现在 **T1579 与 PXJ-H**，且都写成 `<科03 n="kpD03-001">`（给「同值跨著作 → 不同 VA」用）。
- `T1579` 的 `科03 kpD03-001` 其下有交叉引一行含字面 `〔T1580-1#kpD04-003〕`（给 nodeSpanText 断言）。
- `kpD01-001` 在 `T1579` 的 **-1、-4、-21 三卷各一**（`T1579-2` **不要**有 kpD01-001，也**不要**有 kpD03-001）。三者 VA 递增，-21 最大（给「卷级各自精确」「篇级取最后一笔＝-21」「卷内无值→null」）。
- `T1579-1` 里另有 `<科03 n="kpD03-001">`（给钩子 `T1579-1#kpD03-001`）。

**B. 子树 / 节联（v4 段）**
- `T1579-1` 的 `kpD01-001`（`科01`）**必须有 ≥4 层嵌套子科**（`科02/科03/科04…` 逐层往下），最深处一个后代标题字面含 **`五識身相應地`**。这样 `<嵌 sub="1">` 才会渲染出 ≥4 个 `embedTier`、并出现 `padding-left:1.2em` 与 `2.4em`。
- 该子树**不得跨进 `T1579-2`**（`nodeSubtreeEnd` 的界要停在 T1579-1 内）→ 子树文字里不能出现「卷第2」之类。
- 给「叶节点」用：`T1579-1` 里有 `<科04 n="kpD04-001">…</科04>`，其**同层下一兄弟**紧接在后（这样叶的 `subtreeEnd`＝首个界）。
- `<节联>`：fixture 里可放一处 `<节联 n="T1579-1#kpD02-002">…</节联>`（parseLinkSpec 是纯函数，主要给渲染冒烟；可省）。

> 上面每条都对应测试里一句 `ok(...)`；照着建，测试就会从 48/4 回到全绿，且**与正式库后续 v12、v13… 无关**。
